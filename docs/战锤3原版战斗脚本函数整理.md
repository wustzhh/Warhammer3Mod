# 战锤3原版战斗脚本函数整理

> 基于原版脚本文档 `源码/data/documentation/script/battle/`、库实现 `源码/data_script/script/_lib/`，并结合一些MOD的战斗脚本实践整理。  
> 目标：为战役战斗里「脚本驱动特殊能力 / 瞬移 / 生命操作 / 目标捕获」提供可复用的 API 地图与踩坑清单。  
> 文档日期：2026-07-27。原版 HTML 文档最后更新标注约 2026-04-24。

---

## 1. 总览：战斗脚本是什么

战斗脚本运行在**独立于战役的战斗 Lua 环境**中。引擎提供原始 `battle`（`empire_battle`）接口；脚本库再包一层 `battle_manager`（全局常称 `bm`）。

```
引擎 battle setup（部队/地形/胜负条件）
        │
        ▼
加载 Lua（setup 指定路径，或默认 battle_start.lua）
        │
        ├── load_script_libraries() → 创建全局 bm
        ├── 原版任务战 / survival / intro 脚本
        └── core:load_mods("/script/_lib/mod/", "/script/battle/mod/")  ← MOD 自动加载
```

两类常见工作流：

| 类型 | 典型场景 | 推荐入口 |
|------|----------|----------|
| **Generated Battle** | 任务战、剧本战，按军队级发令 | `generated_battle` / `generated_army` |
| **单位级脚本战斗** | 自定义能力编排、瞬移、换血、隐藏技能连发 | `bm` + `script_unit` + `battle_unit` / `unitcontroller` |

**无双英灵录 / RLH 的专属技能逻辑几乎都属于后者**：普通战役战斗也会加载 `script/battle/mod/*.lua`，不依赖任务战 setup。

## 2. 加载机制（MOD 必读）

### 2.1 原版如何挂脚本

战斗 setup 可指定脚本路径，来源包括：

- 战役：`cm:add_custom_battlefield(...)`
- DB：`battle_set_pieces.battle_script`
- 战斗 XML：`<battle_script>` 标签

未指定时加载默认：`script/battle/default_battle/battle_start.lua`（内部 `load_script_libraries()`）。

### 2.2 MOD 自动加载路径

`lib_mod_loader.lua` 在 `core:is_battle()` 时调用：

```lua
core:load_mods(
    "/script/_lib/mod/",
    "/script/battle/mod/"
)
```

因此 MOD 战斗脚本应放在：

```
mod/<你的MOD>/script/battle/mod/<name>.lua
```

文件名排序影响加载顺序（RLH 用 `!!`、`!`、`z_` 等前缀控制先后）。库工具应最先加载（如 `!!rlh_battle_utils_arthas.lua`）。

### 2.3 与战役脚本的关键差异

| 项目 | 战役 | 战斗 |
|------|------|------|
| 管理器 | `cm` | `bm` |
| 监听器 | 常在 `cm:add_first_tick_callback` 内 `core:add_listener` | 顶层即可用 `bm:*`；也可 `bm:register_*` |
| 时间单位 | 秒 | **毫秒**（`bm:callback(fn, 5000)` = 5 秒） |
| 目标 | faction / character / force | alliance → army → unit |
| Lua | Lua 5.1 | 同左（无 `goto` / `//` 等） |

## 3. 对象层级

```
bm / battle
 └── alliances (battle_alliances)          -- 恒为 2 个：1=进攻方，2=防守方
      └── alliance (battle_alliance)
           └── armies (battle_armies)
                └── army (battle_army)
                     └── units (battle_units)
                          └── unit (battle_unit)     -- 只读查询为主
                               + unitcontroller     -- 下命令、改状态
```

实践中几乎总是：

```lua
local sunit = script_unit:new(unit, "my_name")
-- sunit.unit  → battle_unit
-- sunit.uc    → battle_unitcontroller
```

`script_unit` 把「查询 + 控制」打包，并提供 `teleport_to_location`、`cache_location`、`release_control` 等高层封装。

## 4. 核心全局对象

### 4.1 `bm`（battle_manager）

自动创建。可透传底层 `battle` 调用，并额外提供 QoL。

| 类别 | 常用函数 | 说明 |
|------|----------|------|
| 层级访问 | `bm:alliances()` | 与 `battle:alliances()` 相同 |
| 阶段 | `register_phase_change_callback(phase, fn)` | `"Deployment"` / `"Deployed"` / `"VictoryCountdown"` / `"Complete"` |
| 指令 | `register_command_handler_callback(cmd, fn, name?)` | 拦截玩家/AI 指令，如 `"Special Ability"` |
| 定时（模型时间） | `callback` / `repeat_callback` / `remove_process` | 战斗可暂停时随模型走 |
| 定时（真实时间） | `real_callback` / `repeat_real_callback` | 不受暂停影响 |
| 原生 timer | `register_repeating_timer` / `unregister_timer` | **不走 bm 共享 callback 队列**（见实践） |
| 条件轮询 | `watch` / `remove_process` | 条件为真时触发一次 |
| 消息 | `queue_help_message` / `queue_advisor` | 战斗内提示 |
| 收尾 | `register_phase_change_callback("Complete", shutdown)` | 清理 timer / process |

### 4.2 `battle_unit`（查询与部分状态修改）

文档约 **110** 个函数。按用途分组：

#### 身份与归属

| 函数 | 用途 |
|------|------|
| `type()` | `land_units` / `main_units` 键（找专属角色用） |
| `unique_ui_id()` | 本场战斗唯一 ID（缓存、日志、CCO 查询） |
| `name()` | 内部名 |
| `alliance_index()` / `army_index()` | 敌我判断 |
| `is_commanding_unit()` | 是否将军 |
| `army()` | 所属军队 |

#### 位置与运动

| 函数 | 用途 |
|------|------|
| `position()` / `bearing()` | 当前位置、朝向 |
| `ordered_position()` / `ordered_bearing()` / `ordered_width()` | 当前命令目标姿态 |
| `position_of_officer()` | 军官位置 |
| `can_reach_position(pos)` | 可达性 |
| `unit_distance(other)` / `unit_in_range(other)` | 单位间距 |
| `is_moving()` / `is_idle()` / `is_leaving_battle()` | 状态 |

向量辅助（全局）：`v(x,z)` 或 `v(x,y,z)`；`pos:distance_xz(other)` 等。

#### 生命与人数（高频坑点）

| 函数 | 语义（务必分清） |
|------|------------------|
| `unary_hitpoints()` | **当前生命比例**，0~1，相对开战满血 |
| `heal_hitpoints_unary(ratio, allow_rez?)` | 治疗到指定比例（**目标绝对值**，不是增量） |
| `reduce_hitpoints_unary(delta, hide?)` | **扣除**指定比例（是减量） |
| `number_of_men_alive()` / `initial_number_of_men()` | 存活人数 |
| `unary_of_men_alive()` | 人数比例 |
| `kill_number_of_men(n, hide?)` | 杀掉 n 人 |
| `respawn()` | 重生 |

**换血正确写法（女娲阴阳平衡实践）：**

```lua
local a = unit_a:unary_hitpoints()
local b = unit_b:unary_hitpoints()
-- 先缓存再写回
if desired > current then
    unit:heal_hitpoints_unary(desired, false)   -- 设为目标比例
elseif desired < current then
    unit:reduce_hitpoints_unary(current - desired)  -- 扣差值
end
```

#### 士气 / 交战

`is_wavering` / `is_routing` / `is_shattered` / `is_rampaging` / `is_in_melee` / `is_under_missile_attack` / `is_valid_target` / `is_deployed` 等。

#### 特殊能力

| 函数 | 用途 |
|------|------|
| `can_perform_special_ability(key)` | 当前能否施放 |
| `disable_special_ability(key, disabled?)` | 禁用/启用单个能力（默认 disabled=true） |
| `disable_passive_special_abilities(disabled?)` | 批量被动 |
| `disable_non_passive_special_abilities(disabled?)` | 批量主动 |
| `owned_special_abilities()` | 全部能力 key 表 |
| `owned_passive_special_abilities()` / `owned_non_passive_special_abilities()` | 分类列表 |
| `num_special_abilities()` | 数量 |
| `can_use_magic()` | 能否用魔法 |

> `disable_special_ability` 与 batch disable **相互独立**：batch 重新 enable 不会清掉单个 disable。

#### 属性

| 函数 | 用途 |
|------|------|
| `has_attribute(key)` | 单位当前是否带有该属性 |
| `set_stat_attribute(key, enable)` | 脚本开关属性 |

**硬规则（与项目 AGENTS / 开发技能一致）：** 只能使用原版 `unit_attributes_tables` 已有键；禁止新建自定义 attribute。短时目标标记实践中常用原版 `stalk` + `unspottable` 组合。

### 4.3 `battle_unitcontroller`（下命令）

文档约 **77** 个函数。单位**不能**通过 `battle_unit` 下移动/施法命令，必须经 UC。

| 类别 | 函数 |
|------|------|
| 控制权 | `take_control` / `release_control` |
| 施法 | `perform_special_ability(key, target?)` |
| 施法（队列） | `perform_special_ability_q(key, target?)` |
| 对地施法 | `perform_special_ability_ground(key, pos, orient?, width?)` |
| 冷却/次数 | `reset_ability_cooldown(key)` / `reset_ability_number_of_uses(key)` |
| 瞬移 | `teleport_to_location(pos, facing_deg, width_m)` |
| 移动 | `goto_location` / `goto_location_angle_width`（及 `_q` 队列版） |
| 攻击 | `attack_unit` / `attack_location` / `attack_building` 等 |
| 士气行为 | `morale_behavior_fearless` / `rout` / `default` |
| 显隐/启用 | `set_invisible_to_all` / `change_enabled` / `set_invincible` |

`script_unit:teleport_to_location` 内部即封装 UC 瞬移。

### 4.4 `script_unit`（推荐封装）

文档约 **151** 个函数。MOD 最常用：

```lua
local su = script_unit:new(bu, "tag")
su:cache_location()
local pos, b, w = su:get_cached_position(), su:get_cached_bearing(), su:get_cached_width()
su:teleport_to_location(dst_pos, bearing, width)
su:release_control()
su.uc:perform_special_ability(ability_key, target_unit)
```

位置交换（RLH Saelithra 交换）：先两边 `cache_location`，再交叉 `teleport_to_location`。

## 5. 战斗阶段与定时器

### 5.1 阶段名

| Phase | 时机 |
|-------|------|
| `Deployment` | 部署开始（即使跳过部署也会触发） |
| `Deployed` | 进入交战 |
| `VictoryCountdown` | 胜负已定，倒计时 |
| `Complete` | 结束；**务必在此清理 timer / repeat_callback** |

### 5.2 两套定时器：必须分清

| API | 机制 | 适用 |
|-----|------|------|
| `bm:callback` / `bm:repeat_callback` | bm 共享 process 队列 | 一般延迟、轮询 |
| `bm:register_repeating_timer(name, interval_ms)` + **同名全局函数** | 引擎原生 timer | 高频目标捕获；避免被 UC 命令打断 Lua 调用链时丢回调 |

无双英灵录渡鸦/女娲：目标捕获用原生 `register_repeating_timer`，因为：

> 单位控制器命令可能中断当前 Lua 调用链；原生 timer 不依赖 bm 共享 callback 队列。

全局回调函数名必须与 timer 名一致：

```lua
bm:register_repeating_timer("wyccc_duya_dimension_slash_target_capture_timer", 100)

function wyccc_duya_dimension_slash_target_capture_timer()
    capture_dimension_slash_target()
end
```

## 6. 指令拦截：`Special Ability`

```lua
bm:register_command_handler_callback(
    "Special Ability",
    function(context)
        local ability_key = context:get_string1()
        -- 文档保证的字段主要是 ability key
        -- 不要假设 context 直接给出手动点选的目标单位
    end,
    "unique_callback_name"
)
```

实践结论（RLH + 无双英灵录一致）：

1. 用指令事件**只开捕获窗口**（知道「这个能力被按了」）。
2. **目标**靠 DB phase / 原版 attribute 标记 / CCO `ActiveEffectList` 扫描得出。
3. 标记可能在蓄力期间就出现又消失 → 要**提前缓存**目标，等自身 phase 激活再执行。

## 7. CCO：文档外但实战必需的一层

原版 HTML 文档几乎不写 CCO。RLH 工具库与无双英灵录证明，读 **当前生效的 ability phase** 要走：

```lua
common.get_context_value(
    "CcoBattleUnit",
    tostring(unit:unique_ui_id()),
    "ActiveEffectList.Size"
)
-- ActiveEffectList.At(i).PhaseRecordContext.Key
-- NumEntitiesInitial 等
```

RLH `!!rlh_battle_utils_arthas.lua` 封装了：

- `active_effect_phase_set(uid)`
- `has_active_effect_phase(uid, effect_key)`
- `cco_get` / `cco_number` / `cco_string`
- `find_all_units()` / `is_enemy` / `is_alive` 等安全包装（一律 `pcall`）

渡鸦脚本模式：CCO phase 优先；若读不到，则回退到同一 phase 施加的两个原版属性（`stalk` + `unspottable`，要求同时存在）。

## 8. 实践模式对照

### 8.1 随机传奇英雄（RLH）

| 模式 | 代表脚本 | 做法 |
|------|----------|------|
| **工具层** | `!!rlh_battle_utils_arthas.lua` | 全场单位遍历、CCO phase、安全 pcall、日志文件 |
| **Phase 监视瞬移** | `rlh_saelithra1.lua` | 轮询自身 phase → 找带敌方 phase 的单位 → `script_unit:teleport_to_location` |
| **位置交换** | `rlh_saelithra2.lua` | 双边 cache 后交叉瞬移 |
| **集结传送** | `rlh_artanis3.lua` | 多单位延迟传送到将军附近 |
| **隐藏技能连发** | `rlh_zeqotal_awakened_magics.lua`、quest artefact | `disable_special_ability(false)` → `can_perform` → `uc:perform_special_ability` / `_ground` → 再 `disable(true)` |
| **按单位发现** | 多数 | `bm:repeat_callback` 搜索 `type()`，发现后为每单位开 watcher；`Complete` 时 `remove_process` |

典型「脚本施法」骨架：

```lua
bu:disable_special_ability(ability_key, false)
bm:callback(function()
    if not bu:can_perform_special_ability(ability_key) then
        bu:disable_special_ability(ability_key, true)
        return
    end
    su.uc:perform_special_ability(ability_key, target_bu)
    -- 或 perform_special_ability_ground(ability_key, position)
    bm:callback(function()
        bu:disable_special_ability(ability_key, true)
    end, reset_delay_ms)
end, cast_delay_ms)
```

隐藏执行能力：平时禁用，防止 AI/玩家栏外误触；仅在脚本窗口短暂启用。

### 8.2 无双英灵录

| 角色/技能 | 脚本 | 做法 |
|-----------|------|------|
| 渡鸦·次元斩 | `wyccc_hero_duya_battle.lua` | 指令开窗 → 原生 timer 扫目标（CCO phase / 双 attribute）→ 缓存 → 自身 phase 激活后多段 `teleport_to_location` + 隐藏爆炸 `perform_special_ability` |
| 女娲·阴阳平衡 | `wyccc_lord_nvwa_battle.lua` | 指令开窗 → 扫双 attribute 标记目标 → `unary_hitpoints` 缓存后 heal/reduce 互换 |
| 女娲·抟土造人 | 同上 | `repeat_callback` 扫新出现的俑士禁卫，`reduce_hitpoints_unary(0.5)`（首次扫描只建档，避免开局单位被误伤） |

闪现突进类：瞬移与落地爆炸尽量交给 **DB 能力本身**；脚本只编排「多段穿越」这类 DB 做不到的序列。

### 8.3 共用设计原则

1. **DB 能做的别用脚本**（伤害、半径、特保 phase、单次瞬移）。
2. **脚本只做编排**：找单位、读标记、延时、连发、换血、多段瞬移。
3. **目标捕获与效果执行分层**：没有「目标已捕获」日志前，不改伤害/生命 API。
4. **只用原版 attribute** 做脚本可读标记。
5. **所有引擎调用包 `pcall`**；日志用统一前缀（`[wyccc_duya]` / `RLH_Log`）。
6. **战斗结束清理** timer / process，避免泄漏到下一场。

## 9. 推荐工作流（专属战斗技能）

```
① DB：主能力（玩家可见）+ 可选隐藏执行能力（脚本施放）
      + phase（自身特保 / 目标标记）
      + special_ability_phase_attribute_effects（原版 attribute，positive）
② Lua：script/battle/mod/xxx_battle.lua
      - 按 unit:type() 找到角色
      - register_command_handler_callback("Special Ability", ...)
      - 定时扫描标记 / CCO phase
      - 执行 teleport / perform_special_ability / heal·reduce
③ 日志边界（缺哪条查哪层）：
      能力指令收到 → 手动目标捕获 → 瞬移/施法命令发出 → 命中或 HP 变化
```

排查顺序见开发技能「战斗能力目标链与涡流数值排查」：先确认捕获，再动 vortex/伤害。

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 把 `heal_hitpoints_unary` 当增量 | 血量跳到错误比例 | 传**目标比例**；减血用 `reduce` 传差值 |
| 从 `Special Ability` context 猜目标单位 | 目标经常为 nil/错 | phase / attribute / CCO 扫描 |
| 新建 `unit_attributes` | 可能无法启动 | 只用原版键，组合标记 |
| 隐藏技能不 disable | AI/误触乱放 | 默认 disable，窗口内短暂 enable |
| 只靠 `bm:callback` 做高频捕获且紧跟 UC 命令 | 回调丢失 | 原生 `register_repeating_timer` 或先入队再瞬移 |
| 战斗结束不清理 | 下一场异常 | `Complete` 阶段 `unregister_timer` / `remove_process` |
| 无 `pcall` 调引擎 API | 单次失败拖垮整脚本 | 工具函数统一 `safe_call` |
| 用战役思维写 `core:add_listener` 且忘了战斗环境 | 监听不到 | 战斗优先 `bm:register_*` |
